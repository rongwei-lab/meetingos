# MeetingOS 实际需求文档

版本：0.19.0
整理日期：2026-07-21
依据：当前前后端代码、数据库迁移、`CHANGELOG.md`、`docs/api-overview.md`、`docs/data-model.md`、`docs/mvp-acceptance-checklist.md`

## 1. 文档目的

本文档用于描述 MeetingOS 当前已经开发出的真实业务需求、功能边界和验收口径。它不是早期设想清单，而是以当前代码为准反推的产品需求说明，适合后续开发、测试、部署、验收和需求沟通使用。

当前系统是面向会议、论坛、培训、发布会等活动场景的会议管理 MVP，核心覆盖：

- 会议创建、发布、状态流转和工作区管理。
- TDuck 报名表独立集成、报名入口控制、Webhook/补偿同步。
- 参会人管理、审核、标签、导入导出。
- 座位布局、自动排座、手动调座、座位公开查询。
- 住宿房间维护、房间分配、住宿公开查询。
- 晚宴地点时间、桌号容量、桌号分配、晚宴公开查询。
- 后台签到、自助签到、重复签到拦截和签到记录。
- 公开入口页、综合查询页、独立查询页和页面内容配置。
- 统计、导出、操作日志、系统设置、账号与会议级权限。

## 2. 产品定位

MeetingOS 定位为“会议业务主流程管理系统”。TDuck 负责通用表单设计、报名页发布、原始报名采集；MeetingOS 负责将报名数据转成会议业务数据，并继续处理审核、排座、住宿、晚宴、签到、查询、统计和导出。

系统采用 monorepo：

- `meetingos-backend/`：Java 17 + Spring Boot 3.3 后端。
- `meetingos-admin/`：Vue 3 + TypeScript + Vite + Naive UI 后台和公开页。
- `deploy/`：Docker Compose、Nginx、TDuck 集成和部署脚本。
- `docs/`：需求、API、数据模型、测试和专项说明。

TDuck 保持独立部署，不合并到 MeetingOS 源码。MeetingOS 通过 TDuck 管理 API、公开表单地址和 Webhook 与 TDuck 集成。

## 3. 当前范围

### 3.1 当前已纳入 MVP 的范围

- 单会议及多会议后台管理。
- 后台登录、JWT/Cookie 鉴权、全局角色和会议授权。
- TDuck 表单选择、空白表单创建、AI 建表跳转、表单编辑跳转。
- 会议报名中转入口 `/r/{meetingCode}`。
- 报名入口同步启停：同时控制 MeetingOS 中转入口和 TDuck 原始表单发布状态。
- TDuck 字段同步、字段映射、Webhook 同步、单条补偿同步、可恢复的一键拉取全部报名任务。
- 参会人列表、详情、新增、编辑、审核、批量审核、取消、标签，以及排序、列宽调整与本地记忆。
- 参会人席签打印，支持模板背景、字段选择、字号、颜色、字距、加粗、尺寸和 A4 排版预览。
- Excel 导入参会人、房间、房间分配、晚宴分配。
- 座位布局、多区域、默认座位类型、禁用座、锁定座、自动排座、手动排座、交换、清空、导出座位图。
- 住宿房间维护、房间分配、清空分配、导入导出。
- 晚宴桌号、容量、整场晚宴地点时间、手动分配、清空、导入导出。
- 后台扫码/搜索/手工/补签签到。
- 公开座位查询、住宿查询、晚宴查询、综合查询、自助签到、签到码展示。
- 公开查询验证码、单 IP 限流、查询历史和查询汇总。
- 报名、座位、住宿、晚宴、签到统计和趋势/分布；后台列表支持页大小选择、总量摘要与移动端分页。
- XLSX 导出任务和兼容直接下载。
- 操作日志、敏感信息脱敏、品牌/域名/TDuck 地址配置。
- 图片资产上传，用于品牌、公开页 Logo、背景等。

### 3.2 当前明确不纳入的范围

- 在线支付、复杂票务和电子票核销。
- 短信、邮件、微信、小程序等真实通知投递。当前只有通知记录接口，不形成投递闭环。
- 外部酒店预订、酒店房态容量联动、交通行程管理。
- 多会场多场次复杂议程、分论坛、胸牌打印、闸机、人脸识别、身份证读卡。
- 复杂 CRM、营销自动化、会员系统。
- 导出审批流。当前版本已经移除导出审批，导出创建后可直接下载。
- 多副本共享限流和验证码存储。当前公开查询限流、验证码为单实例内存实现。

## 4. 角色与权限

### 4.1 全局角色

系统存在以下全局角色：

| 角色 | 说明 |
| --- | --- |
| `SUPER_ADMIN` | 超级管理员，可访问全部会议、系统设置、用户管理、操作日志。 |
| `MEETING_ADMIN` | 会议管理员，需要被授权到具体会议后才能管理该会议。 |
| `CHECKIN_STAFF` | 签到工作人员，需要会议级 `CHECKIN` 或 `MANAGER` 授权。 |
| `ROOM_STAFF` | 住宿工作人员，需要会议级 `ROOM` 或 `MANAGER` 授权。 |
| `VIEWER` | 只读查看人员，需要会议授权后查看对应会议。 |

### 4.2 会议级授权

会议授权角色包括：

| 会议角色 | 权限范围 |
| --- | --- |
| `MANAGER` | 管理会议、报名配置、参会人、排座、住宿、晚宴、导出、查询配置等。 |
| `CHECKIN` | 访问签到工作台并执行签到。 |
| `ROOM` | 管理住宿相关数据。 |
| `VIEWER` | 查看会议工作区和业务数据，不允许修改。 |

超级管理员不受会议授权限制。其他用户必须同时具备匹配的全局角色和会议级授权。会议管理员创建会议后，应自动获得该会议 `MANAGER` 授权。

### 4.3 参会人角色

参会人不登录后台，通过公开入口完成报名跳转、座位/住宿/晚宴查询、自助签到和签到码查看。公开查询必须受开关、时间窗口、验证码、限流和身份字段约束。

## 5. 主要业务流程

### 5.1 会议创建到报名开放

1. 管理员创建会议，系统生成或保存会议编号。
2. 管理员维护会议名称、时间、地点、容量、简介、议程、联系人、晚宴信息等。
3. 管理员发布会议或调整会议状态。
4. 管理员在报名配置页选择或创建 TDuck 表单。
5. MeetingOS 保存 TDuck 绑定关系，并自动配置 TDuck Webhook。
6. 管理员同步并保存字段映射，至少要映射姓名和手机号。
7. MeetingOS 生成固定中转入口 `/r/{meetingCode}` 和二维码。
8. 管理员开启报名入口后，参会人可通过中转入口跳转到 TDuck 报名。

### 5.2 报名同步到参会人

1. 参会人在 TDuck 填写报名表。
2. TDuck 通过 Webhook 推送报名数据到 MeetingOS。
3. MeetingOS 校验 HMAC 签名或兼容 Token。
4. MeetingOS 根据 `formKey` 找到会议绑定。
5. MeetingOS 根据字段映射提取姓名、手机号、单位、职务、参会类型、住宿需求等字段。
6. 同一会议手机号唯一。相同 `dataId` 更新原参会人；同手机号的新 `dataId` 以提交历史保存，不自动覆盖原参会人的签到、座位、住宿、晚宴和审核状态。管理员可保留现有资料或采用新提交，采用时只替换报名资料与当前 `dataId`。
7. TDuck 删除、撤回、取消类事件不物理删除参会人，而是将参会人置为 `CANCELLED`。
8. 每次成功、失败、重复忽略都写 TDuck 同步日志；待人工裁决的新 `dataId` 不再按失败反复报错，并在报名配置页提供脱敏资料对比与裁决入口。

### 5.3 会务准备

1. 管理员审核或批量审核参会人。
2. 管理员配置座位布局、禁用座、锁定座和座位类型。
3. 管理员自动排座或手动排座。
4. 管理员维护住宿房间和房间分配。
5. 管理员维护晚宴地点时间、桌号容量和桌号分配。
6. 管理员配置公开查询入口、查询字段及其中的必填字段、结果字段、页面文案、开放时间和验证码。

### 5.4 参会人公开查询与自助签到

1. 参会人访问公开入口页。
2. 根据会议配置进入综合查询、座位查询、住宿查询、晚宴查询或自助签到。
3. 系统要求填写配置的必填身份字段，如姓名、手机号、手机号后四位、参会码、单位、职务、邮箱；可选字段未填写时不参与匹配，填写后会参与匹配。
4. 开启验证码时，参会人必须完成数学验证码。
5. 系统默认只允许唯一匹配且审核通过的参会人查询；开启多结果模式后，可返回最多 20 条审核通过参会人的结果。
6. 查询结果按配置展示座位、房间或晚宴字段，并可按配置脱敏或高亮。
7. 自助签到复用公开身份校验；管理员可配置核验成功后直接签到，或先显示脱敏身份信息并由参会人确认后再写入签到记录。
8. 所有公开查询和自助签到结果写入查询历史，用于后台查看查询轨迹和汇总。

### 5.5 现场签到

1. 工作人员进入签到工作台。
2. 支持扫码、完整二维码内容、参会码、手机号、姓名搜索、补签。
3. 系统校验会议、参会人归属、审核状态和签到状态。
4. 未审核、未找到、会议不匹配时返回明确提示并记录签到尝试。
5. 首次成功签到写入参会人签到状态和签到记录。
6. 重复签到不覆盖首次签到，返回首次签到时间、入口和操作人。
7. 补签必须填写原因。

## 6. 功能需求

### 6.1 登录、账号与用户管理

- 系统应支持后台登录、退出和当前用户信息获取。
- 后台接口默认需要认证，公开接口和 Webhook 例外。
- 用户管理支持用户列表、创建用户、编辑显示名/状态/角色、重置密码。
- 内置演示管理员账号在初始化数据中为禁用状态；生产应通过环境变量创建强密码管理员。
- 用户权限不能只看全局角色，除超级管理员外，还必须结合会议授权判断。

### 6.2 会议管理

会议应支持以下字段：

- 会议编号、会议名称、主办方、承办方。
- 开始时间、结束时间、报名开始时间、报名截止时间。
- 地点、会场名称、容量。
- 简介、议程、封面图、联系人、联系电话。
- 晚宴地点、晚宴时间。
- 座位查询、住宿查询、晚宴查询、查询后签到、自助签到等公开入口开关。
- 公开查询字段、其中的必填字段和匹配模式。

会议状态包括：

| 状态 | 说明 |
| --- | --- |
| `DRAFT` | 草稿。 |
| `REGISTRATION_OPEN` | 报名中。 |
| `REGISTRATION_CLOSED` | 报名截止。 |
| `READY` | 待开始。 |
| `IN_PROGRESS` | 进行中。 |
| `ENDED` | 已结束。 |
| `ARCHIVED` | 已归档。 |

系统应支持创建、编辑、分页查询、详情查看、删除和状态流转。会议列表和详情应展示报名数、审核通过数、已排座数、已安排住宿数、已安排晚宴数、已签到数。

### 6.3 TDuck 报名配置

系统应支持以下能力：

- 从 TDuck 拉取表单列表，支持关键字搜索。
- 创建 TDuck 空白表单，并跳转到 TDuck 编辑器。
- 跳转 TDuck AI 智能建表入口。
- 同步 TDuck 浏览器登录态后打开 TDuck 工作台或当前表单编辑器。
- 为会议绑定一个 TDuck 表单。
- 绑定前校验 TDuck 表单真实存在且可访问。
- 保存绑定时自动调用 TDuck Webhook 配置接口。
- 已有效绑定的会议默认禁止改绑其他表单，避免历史报名源混乱；绑定失效时允许重新选择。
- 报名入口开关应同时控制 MeetingOS `/r/{meetingCode}` 和 TDuck 原始 `/tduck/s/{formKey}`。
- 当前绑定状态应展示绑定是否有效、TDuck 是否发布、Webhook 是否已配置、是否允许改绑。

字段映射要求：

- 系统应同步 TDuck 表单字段，并按 TDuck 字段顺序展示。
- 系统应支持把 TDuck 字段映射到 MeetingOS 标准参会人字段。
- 姓名和手机号为必需映射。
- 字段同步应保留管理员已保存的人工映射和“明确不映射”选择。
- 新字段可根据字段名启发式自动识别，但不能覆盖已有人工映射。
- 字段映射保存后，后续 Webhook 和补偿同步都使用同一套映射规则。

补偿同步要求：

- 支持手工提交单条 TDuck payload 补偿同步。
- 支持按 TDuck `dataId` 拉取单条报名详情并同步。
- 支持一键拉取当前绑定表单全部报名，单条失败不能中断整批；任务创建后异步执行并提供进度查询。
- 一键同步使用会议级互斥、幂等键和数据库租约，服务重启或进程中断后可恢复；最多返回有限失败样例，完整错误进入同步日志。
- 只有历史成功日志才作为幂等重复依据；失败日志允许修复后重试。

### 6.4 参会人管理

参会人字段包括：

- 姓名、手机号、单位、职务、证件号、邮箱。
- 参会类型：`VIP`、`GUEST`、`MEDIA`、`STAFF`、`NORMAL`。
- 是否需要住宿、房间号、房间备注。
- 备注、标签。
- 审核状态、审核原因、审核备注、审核人、审核时间。
- 报名时间、参会码、TDuck 数据 ID、原始报名快照。
- 签到状态、签到时间、签到入口、签到操作人。

参会人审核状态包括：

| 状态 | 说明 |
| --- | --- |
| `PENDING` | 待审核。 |
| `APPROVED` | 已通过。 |
| `REJECTED` | 已拒绝。 |
| `CANCELLED` | 已取消。 |

系统应支持：

- 手工新增、编辑、查看详情、取消参会。
- 按关键词、审核状态、签到状态、参会类型、是否有座位、标签筛选。
- 单人审核、批量审核、填写拒绝原因和备注。
- 标签维护。
- Excel 导入参会人，返回失败行和失败原因。
- XLSX 导出参会人或审核通过名单。
- 列表和详情按系统设置对手机号、证件号、邮箱及原始报名快照脱敏。
- 参会人列表应显示座位、住宿、晚宴是否已安排，以及座位/住宿/晚宴是否被公开查询过。

约束：

- 同一会议手机号唯一。
- TDuck 同步进来的新报名当前默认置为审核通过。
- 拒绝或取消已进入后续流程的参会人时，应避免误删排座、住宿、晚宴和查询历史线索。

### 6.5 座位管理

座位管理应支持：

- 按会议创建或更新座位区域。
- 区域字段包括会场名称、区域名称、排数、每排座位数、排序、编号规则、过道设置、舞台方向、默认座位类型。
- 支持区域改名，改名时保留原座位 ID、锁定状态和已有分配。
- 支持缩小布局，但不得删除已有分配或不能安全删除的座位。
- 支持删除空区域。
- 支持座位类型：`NORMAL`、`VIP`、`GUEST`、`MEDIA`、`STAFF`、`DISABLED`。
- 支持座位状态：空座、已分配、已签到、禁用。
- 支持单座锁定/解锁、修改座位类型、启用/禁用座位。
- 禁用座位前必须确认座位未被分配；禁用时自动取消锁定。

自动排座规则：

- 只处理审核通过且未排座的参会人。
- 不覆盖已有手动座位。
- 不使用已锁定、已禁用或已分配座位。
- 先按参会类型优先级分组，再按单位尽量相邻。
- 座位不足时返回跳过数量和警告信息。

手动排座规则：

- 支持把参会人手动分配到指定座位。
- 支持两个已排座参会人交换座位。
- 支持清空某参会人座位。
- 不允许跨会议分配或交换。
- 不允许把未审核通过参会人分配到座位。
- 不允许把参会人分配到禁用座或已被占用座位。

公开座位查询：

- 只允许查询审核通过且已排座参会人。
- 可返回座位区域、排号、座号、座位码和局部座位图。
- 座位图只有在区域、排号、座号均可见且未脱敏时返回。

### 6.6 住宿管理

住宿房间字段包括：

- 房间号、房型、酒店名称、备注、容量、状态。

系统应支持：

- 手工新增房间。
- 查询当前会议房间列表。
- Excel 导入房间号。
- 给参会人分配房间号和房间备注。
- 清空参会人房间分配。
- 导入房间分配。
- 导出住宿安排和房间库存。

约束：

- 同一会议房间号唯一。
- 房间分配以参会人表中的房间号为当前主数据。
- 当前 MVP 允许多人共用同一房间，不做酒店房态容量的强一致校验。
- 公开住宿查询只允许审核通过且已安排房间的参会人查看。

### 6.7 晚宴管理

晚宴采用“会议级地点时间 + 桌号容量 + 参会人桌号分配”的模型。

系统应支持：

- 维护整场晚宴地点和时间。
- 新增、编辑、删除桌号。
- 桌号字段包括桌号、容量、备注、已安排人数、剩余人数、超员人数。
- 手动给参会人安排桌号。
- 清空参会人晚宴安排。
- 导入晚宴分配。
- 导出晚宴安排。
- 查询晚宴安排列表和桌号容量列表。

约束：

- 同一会议同一桌号唯一。
- 桌号容量最小为 1。
- 调整容量时不能小于当前已安排人数。
- 删除桌号前必须先清空该桌人员。
- 同一会议同一参会人只能有一条晚宴安排，重复导入应更新原安排。
- 导入旧格式分配表时，如果桌号尚未维护，可自动补建默认容量桌号。
- 公开晚宴查询只允许审核通过且已安排桌号的参会人查看。

### 6.8 签到管理

签到类型包括：

- `SCAN`：扫码签到。
- `SEARCH`：搜索签到或自助签到。
- `MANUAL`：手工签到。
- `SUPPLEMENT`：补签。

签到结果包括：

- `SUCCESS`：签到成功。
- `DUPLICATE`：重复签到。
- `NOT_APPROVED`：报名未审核通过。
- `NOT_FOUND`：未找到参会人。

系统应支持：

- 后台签到入口。
- 扫码枪输入紧凑签到码。
- 解析完整二维码内容。
- 按手机号或姓名搜索签到。
- 按参会码签到。
- 补签，补签必须填写原因。
- 查询签到记录。
- 生成公开签到码内容。

重复签到规则：

- 每个参会人只有一个当前签到状态。
- 首次成功签到写入参会人表。
- 后续重复签到只记录尝试，不覆盖首次签到时间、入口和操作人。
- 并发扫码时应锁定参会人行，避免多入口同时成功。

### 6.9 公开入口与查询配置

公开入口包括：

- `/r/{meetingCode}`：报名中转入口。
- `/public/entry?token={publicQueryToken}`：公开入口页。
- `/public/query`：综合查询页。
- `/public/seat-query`：座位查询页。
- `/public/room-query`：住宿查询页。
- `/public/dinner-query`：晚宴查询页。
- `/public/checkin`：独立自助签到页。
- `/public/checkin-code`：签到码展示页。

公开查询配置应支持：

- 开关：座位查询、住宿查询、晚宴查询、查询后签到按钮、独立自助签到页。
- 页面级查询后签到按钮开关：综合查询、座位查询、住宿查询和晚宴查询页可分别控制是否展示结果后签到入口。
- 暂停查询。
- 开放开始时间和结束时间。
- 查询字段：姓名、手机号、手机号后四位、参会码、单位、职务、邮箱；每个字段可配置为必填或可选，至少保留一个必填字段。
- 匹配模式：模糊匹配、精确匹配。
- 多结果模式：默认关闭；开启后允许同一查询条件返回多名审核通过参会人的公开结果，用于同手机号或团体代查场景。
- 综合查询展示类型：座位、住宿、晚宴、签到。
- 页面主题色、Logo、背景图。
- 入口页、综合查询页、座位页、住宿页、晚宴页、自助签到页的独立文案配置。
- 按结果类型配置可见字段、脱敏字段和高亮字段。

公开查询安全规则：

- 单 IP 默认每分钟最多 30 次公开请求。
- 验证码可通过配置开启；验证码为数学题，有效期至少 60 秒，默认 300 秒。
- 综合查询可能并发调用多个查询接口，同一个验证码短时间最多允许成功使用 3 次。
- 查询必须满足会议未暂停、在开放时间窗口内、入口开关已开启。
- 必须填写所有配置的必填查询字段；可选字段填写后才参与匹配。
- 默认只允许唯一匹配；匹配多条时提示补充更精确信息，不返回候选列表。
- 开启多结果模式后，单次公开查询最多返回 20 条审核通过参会人的结果，避免候选列表过度暴露。
- 只允许审核通过参会人查询。
- 查询成功和失败都写公开查询历史。
- 公开查询历史记录查询类型、状态、输入摘要、错误信息、关联参会人、结果摘要、IP 和 User-Agent。

### 6.10 报名入口中转

报名中转应满足：

- 报名二维码内容固定使用 MeetingOS 中转地址 `/r/{meetingCode}`。
- 公开查询入口二维码或链接应使用随机 `publicQueryToken`，避免通过顺序会议 ID 或会议编号枚举公开查询配置。
- 系统应根据会议状态、报名时间、TDuck 绑定、报名入口开关和 TDuck 表单可用性判断是否开放。
- 会议处于“进行中”时仍可开放报名，最终由报名时间窗口、TDuck 发布状态和报名入口开关共同决定。
- 若不可报名，应在 MeetingOS 公开页展示明确原因，而不是直接跳到 TDuck 空状态。
- 中转响应不应被浏览器缓存。

### 6.11 统计

统计应支持当前会议概览和按日期范围统计，范围最长 366 天。

统计指标包括：

- 报名总数、时间范围新增、今日新增、待审核、已通过、已拒绝。
- 总座位、可用座位、已分配、空余、禁用、座位使用率。
- 房间总数、需住宿人数、需住宿已安排、需住宿未安排、住宿已安排、住宿未安排。
- 晚宴已安排人数。
- 已签到、未签到、签到率、时间范围签到。
- 报名趋势、签到趋势。
- 审核状态分布、参会类型分布、单位分布、酒店分布、房型分布、签到入口分布、签到方式分布。

趋势数据需要补齐没有数据的日期，避免前端图表断点。

### 6.12 席签打印

席签打印支持：

- 从参会人列表选择当前筛选结果或批量勾选人员后打印席签。
- 支持 60x90mm、80x120mm、100x200mm、100x220mm 等常用折后单面尺寸。
- 支持上传会议级席签模板背景，模板 URL 只允许同源 `/uploads/` 图片或 HTTPS 图片。
- 支持选择姓名、单位、职务、手机号、参会类型、座位号、房间号、晚宴桌号、参会码和标签等展示字段。
- 每个展示字段可配置字号、颜色、字距和是否加粗，字段顺序即打印顺序。
- 打印预览按 A4 纸自动判断单张或双张排版，生成上下两面内容，沿中线对折使用。

后台接口为 `GET /api/admin/meetings/{id}/print-settings` 和 `PUT /api/admin/meetings/{id}/print-settings`。查看需要会议查看权限，保存需要会议管理权限，并写入操作日志。

### 6.13 导出

导出支持：

- 创建导出任务。
- 查询导出任务列表。
- 下载导出文件。
- 界面和接口默认 XLSX；显式 `format=csv` 仅用于兼容旧调用。
- 导出下载写操作日志。

导出类型包括：

- `attendees`：参会人。
- `approved`：审核通过名单。
- `no-checkin`：未签到名单。
- `rooms` / `accommodations`：住宿安排。
- `room-inventory`：房间库存。
- `dinner`：晚宴安排。
- `seats`：座位表。
- `checkin` / `checkin-records`：签到记录。
- `statistics`：统计数据。

当前版本导出审批已移除。导出任务创建后状态为已完成，可直接下载。敏感字段导出是否脱敏由系统设置中的脱敏开关决定。

### 6.14 操作日志

系统应对关键后台操作写操作日志，包括但不限于：

- 创建、编辑、删除、状态流转会议。
- TDuck 表单绑定、报名入口开关、字段映射、补偿同步。
- 参会人新增、编辑、审核、批量审核、取消、标签、导入导出。
- 座位布局、自动排座、手动排座、换座、清座、锁座、禁用座。
- 房间创建、导入、分配、清空、导出。
- 晚宴桌号、分配、清空、导入导出。
- 签到、补签、重复签到尝试。
- 会议席签打印设置更新。
- 导出创建和下载。
- 系统设置更新、通知记录创建。

操作日志只允许超级管理员查看。日志详情应递归脱敏手机号、证件号、邮箱、Token、密码和密钥类字段。

操作日志列表支持按业务分类、成功或失败、日期范围和关键词筛选，首次请求会固定最大日志 ID，保证翻页期间不混入新记录。默认不展示邀请函草稿保存；列表响应不返回客户端 IP、原始 details 或 Webhook 原始载荷。

系统会审计成功登录、退出、公开自助签到和已验签 TDuck Webhook 的同步结果。操作日志默认保留 90 天，后端每天按部署时区清理超过保留期的记录；保留天数和清理时间可通过环境变量配置，恢复历史记录只能依赖数据库备份。

### 6.15 系统设置与品牌

系统设置应支持：

- MeetingOS 对外域名。
- TDuck 前端地址。
- TDuck 后端 API 地址。
- 敏感信息脱敏开关。
- 品牌名称。
- 浏览器标题。
- Meta 描述。
- Logo URL。
- favicon URL。

安全要求：

- Webhook Token 不允许通过后台写入数据库，只能通过 `TDUCK_WEBHOOK_TOKEN` 环境变量管理。
- 后台只展示 Webhook Token 是否已配置和脱敏后的状态。
- Logo 和 favicon 只允许同源 `/uploads/` 图片、`/favicon.svg` 或 HTTPS 图片地址。
- 图片上传接口只允许后台认证用户使用，公开访问只开放 `/uploads/**` 读取。

### 6.15 通知记录

当前系统已有通知记录接口，支持：

- 按会议查看通知记录。
- 创建通知记录，字段包括标题、内容、渠道、范围、状态、预计人数。

当前通知模块只记录通知计划或草稿，不负责短信、邮件、微信等真实发送，也不提供投递状态回调。

### 6.16 邀请函与渠道归因

系统支持在同一会议下创建、复制并同时发布多份公开邀请方案。每份方案包含独立的 H5 和海报设计，
草稿修改通过修订号避免多人覆盖；发布生成不可变版本，并固化当时的会议名称、时间、地点、议程和
联系人等公开字段。已发布方案可下线或归档，历史渠道和归因数据不得物理删除。

邀请函设计器使用受控领域元素，不允许任意 HTML、脚本或 Fabric 原始 JSON。H5 支持文字、会议字段、
图片、形状、报名按钮、二维码、倒计时、HTTPS 音视频、轮播和高德地图；海报只输出静态元素和互动
组件的封面/文字降级。图片必须属于当前会议素材库，音视频不在一期上传或转码。

管理员可为每份方案创建微信好友、朋友圈、邮件、线下海报或自定义渠道链接。系统统计可见页面访问、
匿名访客、报名点击、TDuck 首次提交和当前有效报名；人工复制链接或下载二维码不等同于真实触达。
同一会议的所有方案继续共用当前唯一 TDuck 表单，不提供自动 A/B 分流。

匿名访客使用随机一方 Cookie，数据库仅保存不可逆 HMAC，不保存原始 IP 或完整 User-Agent。报名点击
token 经 TDuck `extValue` 回传，缺失或校验失败只记为未归因，不能影响参会人同步。历史答卷标记为
历史未归因，取消报名保留累计转化但不计入当前有效报名。

## 7. 数据与安全要求

### 7.1 敏感信息

以下信息在列表、详情、日志、同步 payload 展示时应支持脱敏：

- 手机号。
- 证件号。
- 邮箱。
- Token、密码、密钥类字段。
- TDuck 原始报名 payload 中的敏感字段。

导出字段是否脱敏由系统设置控制。生产环境建议默认开启脱敏。

### 7.2 Webhook 安全

- 推荐使用 `X-TDuck-Signature: sha256=<HMAC_SHA256(raw_body, TDUCK_WEBHOOK_TOKEN)>`。
- 兼容 `X-MeetingOS-Webhook-Token` 请求头。
- 兼容内网 query token，但不建议在公网 URL 使用 query token。
- 签名失败必须拒绝请求并写同步失败日志。
- 错误响应不应暴露密钥细节。

### 7.3 公开查询安全

- 默认单 IP 每分钟 30 次。
- 公开查询 API 只接受随机 `publicQueryToken` 定位会议，不接受顺序 `meetingId` 或可猜测会议编号。
- 是否信任 `X-Forwarded-For` / `X-Real-IP` 必须由部署配置控制。
- 若后端可被公网直连，不得信任转发头，避免绕过限流。
- 验证码和限流当前为内存实现，多副本生产环境应迁移到 Redis 或网关层。

### 7.4 数据边界

- MeetingOS 不直接读写 TDuck 业务表。
- MeetingOS 保存 TDuck 绑定、字段映射、同步快照和同步日志。
- TDuck 原始 payload 可用于排障，但 MeetingOS 的参会人、排座、住宿、晚宴、签到应使用 MeetingOS 自有主数据。
- TDuck 删除/撤回不物理删除 MeetingOS 参会人，改为取消状态并保留审计线索。

## 8. 部署与运行要求

- 后端运行环境：Java 17、Spring Boot 3.3、MySQL、Flyway。
- 前端运行环境：Node >= 20、Vue 3、Vite。
- TDuck 独立部署，推荐同域代理为 `/tduck/` 与 `/tduck-api/`。
- Nginx 需要转发 `/api/`、`/r/`、`/public/`、`/uploads/`、`/tduck/`、`/tduck-api/`、`/u/`。
- `.env` 中数据库密码、JWT Secret、TDuck 管理员账号、`TDUCK_WEBHOOK_TOKEN` 必须替换为强随机值。
- 生产环境必须配置真实 HTTPS。
- MySQL、Redis、MinIO 不应暴露到公网。
- 生产镜像应固定版本 tag 或 digest。
- 备份应覆盖 MySQL、Redis 持久化数据和上传文件。

## 9. 当前实现提示

- 后台 API 以 `/api/admin` 为主，保留部分 `/api` 旧路径兼容。
- 公开接口以 `/api/public` 为主。
- TDuck Webhook 推荐路径为 `/api/integrations/tduck/webhook`。
- 当前数据库迁移包含 `V1` 到 `V7`。`V1` 是新库基线，后续迁移依次补充席签打印、TDuck 幂等、异步文件任务、邀请函归因、性能索引和 TDuck 拉取任务。历史库升级需要关注 Flyway 历史、checksum 风险和重复 TDuck 主键数据。
- 当前版本前端启用 Naive UI 中文语言包和日期语言包。
- TDuck 前端部署补丁会调整品牌文案、AI 建表跳转和 `/u/` 上传资源代理。
