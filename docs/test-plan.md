# MeetingOS MVP 测试计划

本文档用于指导开发联调、测试执行和上线前回归。

## 测试范围

覆盖以下 MVP 模块：

- 会议管理
- TDuck 报名表绑定、字段映射、Webhook 同步
- 参会人审核、导入、导出
- 座位布局、自动排座、手动调座、座位查询
- 房间录入、导入、分配、房间查询
- 扫码签到、搜索签到、补签、重复签到
- 统计、权限、操作日志
- Docker Compose 和 Nginx 部署

## 测试环境

推荐使用与生产接近的 Compose 环境：

```bash
cd deploy
docker compose --env-file ../.env --profile tduck up -d
```

基础验证：

- `/` 能打开 MeetingOS 前端。
- `/api/actuator/health` 或后端健康检查接口返回正常。
- `/tduck/` 能打开 TDuck 前端。
- `/tduck-api/` 能访问 TDuck 后端 API。
- MinIO 控制台能登录，bucket 已创建。

## 测试数据

建议准备：

- 2 个会议：一个报名中，一个已截止。
- 1 个 TDuck 表单，包含姓名、手机号、单位、职务、参会类型、是否住宿、备注。
- 30 条参会人，其中包含重复手机号、缺手机号、手机号格式错误、VIP、嘉宾、媒体、工作人员、普通参会人。
- 100 个座位，其中包含 VIP 区、嘉宾区、媒体区、普通区和禁用座位。
- 20 个房间，包含不同酒店、楼栋、楼层、房型。
- 3 个角色账号：会议管理员、签到工作人员、住宿工作人员。

## 功能测试

### 会议管理

- 创建会议，校验必填字段。
- 修改会议时间、地点、人数上限。
- 发布会议后生成报名入口。
- 报名截止后访问 `/r/{meetingCode}`，确认不再跳转 TDuck。
- 归档会议后确认普通业务操作受限。

### TDuck 集成

- 绑定合法 `formKey`。
- 保存字段映射，缺少姓名或手机号时应失败。
- 使用正确 Token 推送 `form_data_add`，应生成参会人。
- 使用错误 Token 推送，应返回未授权并记录安全日志。
- 推送缺少手机号的数据，应进入失败同步日志。
- 推送重复手机号，应按策略更新或标记重复待处理。

### 参会人

- 列表分页、筛选、搜索。
- 单个审核通过、拒绝、取消。
- 批量审核。
- 标签维护。
- Excel 导入成功和失败行提示。
- 导出权限校验和操作日志。

### 座位

- 创建座位布局。
- 自动排座，验证类型优先级和禁用座跳过。
- 手动分配座位。
- 交换两个参会人座位。
- 锁定座位后重新自动排座，确认不被覆盖。
- 清空座位。
- 公开座位查询的成功和失败提示。

### 住宿

- 录入房间号。
- 导入房间号，验证重复房间、空房间号失败。
- 手动分配房间。
- 导入房间分配，验证手机号、证件号、姓名加单位匹配。
- 修改房间，检查操作日志记录原值和新值。
- 公开房间查询的成功和失败提示。

### 签到

- 扫描紧凑签到码。
- 扫描完整二维码内容。
- 手机号搜索签到。
- 姓名搜索签到。
- 未审核通过参会人签到失败。
- 重复签到返回首次签到信息。
- 补签必须填写原因。
- 签到统计更新。

## 权限测试

- 签到工作人员只能访问签到工作台和有限统计。
- 住宿工作人员只能维护住宿相关数据。
- 只读账号不能审核、排座、分房、签到或导出敏感数据。
- 会议管理员不能访问未授权会议。
- 普通管理员不能删除操作日志。
- 会议管理员创建会议后可继续查看、编辑和流转自己创建的会议。
- 系统设置接口只允许超级管理员访问；Webhook Token 仅由 `TDUCK_WEBHOOK_TOKEN` 环境变量管理，后台保存配置不能覆盖密钥。

## 安全测试

- 弱密码、默认密码上线检查。
- JWT 过期、伪造、缺失时接口拒绝访问。
- Webhook Token 缺失或错误时拒绝访问。
- 公共查询接口无法通过暴力枚举批量获取手机号或房间号。
- 导出文件只包含当前用户有权限查看的字段。
- 日志不输出完整证件号、手机号、Token、JWT。
- TDuck 同步日志和签到记录快照在后台响应中脱敏。

## 性能与并发测试

- 参会人列表 1 万条分页查询响应可接受。
- 1000 座座位图加载和查询可接受。
- 签到接口单次响应建议 1 秒内。
- 对同一参会人并发发起 20 次签到，只允许 1 次成功。
- 大文件导入失败时不影响已有数据。
- 导出大名单时应异步或限制规模，避免阻塞现场签到。

## 部署回归

- `docker compose --env-file ../.env.example config` 能通过。
- Nginx 配置能通过语法检查。
- 停止并重启容器后数据仍保留。
- MySQL 备份和恢复流程至少验证一次。
- Redis 重启后 TDuck 业务可恢复；MeetingOS 当前公开查询限流仍为本机内存，多副本上线前需切换为 Redis。
- MinIO bucket 存在，TDuck 上传下载正常；MeetingOS 当前导出仍实时生成 CSV，异步导出落对象存储后需补充文件上传下载回归。

## 上线前准出标准

- P0/P1 缺陷清零。
- 核心报名、审核、排座、住宿、签到链路通过端到端测试。
- 默认密码、`TDUCK_WEBHOOK_TOKEN`、JWT Secret 已替换为强随机值。
- 备份、恢复、日志和权限策略完成检查。
- 已形成 TDuck 联调记录和字段映射表。
