# MeetingOS MVP 验收清单

本清单用于功能验收、联调验收和上线前走查。

## 1. 基础部署

- [ ] Docker Compose 能启动 MySQL 8.4、Redis、MinIO、MeetingOS 后端、MeetingOS 前端 Nginx。
- [ ] 可选 TDuck profile 能启动 TDuck 后端和前端，或已配置外部 TDuck 地址。
- [ ] Nginx 路由 `/`、`/api/`、`/tduck/`、`/tduck-api/`、`/r/{meetingCode}` 符合预期。
- [ ] `.env` 中所有 `CHANGE_ME` 均已替换。
- [ ] 生产域名已配置 HTTPS。
- [ ] `[自动化/MySQL 8.4]` 使用一次性空库执行 `MigrationChecksumTest` 和
  `FlywayMySqlMigrationTest`，V1→V10、Flyway validate、迁移 SHA-256 清单和生产 V1 checksum 全部
  通过；缺少 `MEETINGOS_MYSQL_MIGRATION_TEST_*` 导致的测试跳过不计为通过，checksum 不一致时禁止
  修改 V1 或执行 `flyway repair`。

## 2. 账号与权限

- [ ] 首次初始化管理员可登录。
- [ ] 初始管理员密码已修改。
- [ ] TDuck 默认管理员密码已修改，未继续使用 `123456`。
- [ ] 超级管理员、会议管理员、签到工作人员、住宿工作人员、只读查看人员权限符合设计。
- [ ] 未授权用户无法访问无权限会议、导出接口和系统配置。
- [ ] 会议管理员创建会议后自动获得该会议管理权限。
- [ ] 系统设置可保存 MeetingOS 域名、TDuck 地址和脱敏/导出策略；Webhook Token 仅通过 `TDUCK_WEBHOOK_TOKEN` 环境变量管理。

## 3. 会议管理

- [ ] 可创建会议并维护基础信息、时间、地点、人数上限、状态。
- [ ] 可按名称、状态、开始时间、主办方、创建人筛选会议。
- [ ] 会议详情能展示报名、座位、住宿、签到统计入口。
- [ ] 发布、结束、归档流程状态正确。

## 4. TDuck 报名集成

- [ ] 可绑定 TDuck `formKey`、表单名称和报名页 URL。
- [ ] 可保存姓名、手机号等字段映射。
- [ ] 字段映射缺少必填项时有明确提示。
- [ ] `/r/{meetingCode}` 在报名开放时跳转到 `/tduck/s/{formKey}`。
- [ ] 报名未开始、报名截止、会议不存在时展示明确提示。
- [ ] TDuck Webhook Token 校验生效。
- [ ] Webhook 新增报名能生成参会人和同步日志。
- [ ] 异常 Webhook 不丢失，能在同步日志中看到失败原因。
- [ ] 同步日志可按成功、失败、重复忽略状态筛选；筛选日志不影响最近 Webhook 状态判断。
- [ ] 同步日志详情中的空 TDuck 字段显示表单标题和空值占位，不显示内部字段 key。
- [ ] 同手机号、不同 TDuck `dataId` 的新提交进入待处理列表，可脱敏对比资料并选择保留现有或采用新提交。
- [ ] 采用新提交不改变参会人 ID、审核、签到、座位、房间和晚宴分配；旧当前来源撤回时仅恢复曾被替代的报名。

## 5. 参会人管理

- [ ] 参会人列表能展示姓名、手机号、单位、类型、审核、座位、住宿、签到状态。
- [ ] 支持姓名、手机号、单位、参会类型、审核状态、排座状态、签到状态筛选。
- [ ] 支持单个审核、批量审核、拒绝原因和审核备注。
- [ ] 同一会议同一手机号重复报名能被识别。
- [ ] 支持标签维护和筛选。
- [ ] Excel 导入失败行能返回原因。
- [ ] 导出受权限控制，并写操作日志。

## 6. 座位管理

- [ ] 可配置会场、区域、排数、座位数、座位类型、禁用座位。
- [ ] 可生成至少 1000 座规模的座位图。
- [ ] 自动排座只处理已审核通过且未排座参会人。
- [ ] 自动排座不覆盖手动座位、锁定座位和禁用座位。
- [ ] VIP、嘉宾、媒体、工作人员、普通参会人优先级符合规则。
- [ ] 支持手动分配、交换、清空、锁定座位。
- [ ] 参会人可查询座位；未审核、未排座、未开放查询时提示明确。

## 7. 住宿管理

- [ ] 可逐条录入房间号。
- [ ] 可通过 Excel 导入房间号，重复房间和空房间号能提示。
- [ ] 可给嘉宾手动分配房间。
- [ ] 可导入嘉宾房间分配，支持手机号、证件号、姓名加单位匹配。
- [ ] 房间变更记录原房间、新房间、操作人、操作时间和原因。
- [ ] 嘉宾可查询房间号；未审核、未安排、未开放查询时提示明确。

## 8. 签到管理

- [ ] 签到工作台支持扫码枪输入紧凑签到码。
- [ ] 签到工作台支持完整二维码内容解析。
- [ ] 支持手机号或姓名搜索签到。
- [ ] 未审核通过、会议不允许签到、参会人不存在时提示明确。
- [ ] 重复签到不覆盖首次签到记录。
- [ ] 高并发重复扫码只允许一笔成功，其余返回首次签到信息。
- [ ] 补签必须填写原因并写日志。
- [ ] 签到统计实时更新。

## 9. 邀请函与渠道归因

本节所有复选框默认未验收。`[自动化]` 要求在待发布提交上留存命令结果，`[人工]` 要求留存截图、导出
文件或网络记录，`[真实 TDuck]` 只能在包含部署补丁的真实表单环境验收，mock 或直接构造 Webhook 不算
替代证据。

- [ ] 同一会议可创建并同时发布多份邀请方案，复制、下线和归档不破坏历史数据。
- [ ] `[自动化]` `meetingos-admin` 的 Vitest、类型检查和生产构建全部通过；`meetingos-backend` 的
  邀请函、事件、归因、Webhook 和统计相关测试全部通过，结果中没有被忽略的失败。
- [ ] `[人工/中文 IME]` 在 375px H5 中输入“中文内联编辑 · 会议邀请”，选词、退出编辑、保存和强制
  重载后文字完整，`x/y/width/height` 误差不超过 1 个逻辑像素，旋转误差不超过 0.1°；Vitest 的文本
  回写用例不能替代本项。
- [ ] `[人工/编辑器]` H5 与海报草稿可独立编辑；拖拽、累计缩放、中心旋转、多选、撤销/重做后保存
  重载，最终位置、尺寸、层级、锁定和样式一致。
- [ ] 设计文档拒绝超限元素、跨会议素材、非 HTTPS 音视频和任意未知属性。
- [ ] 每个渠道生成独立 H5 链接；二维码可选择报名、查询入口、综合、座位、住宿或晚宴用途，下方说明可编辑或隐藏。
- [ ] H5 可添加签到按钮和单目标查询按钮；查询目标可配置且点击不会写入报名 CTA，海报不接受这两类互动按钮。
- [ ] `[人工/海报]` 从当前发布版本和已启用渠道导出的正式 PNG 恰好为 1080×1920 且存在非背景像素；
  二维码外框为正方形，独立扫码器/ZXing/`zbarimg` 解码结果逐字符等于当前用途目标；报名用途必须
  携带当前渠道 `shareToken`，查询用途必须携带会议 `publicQueryToken`。草稿导出带
  “预览”标识。
- [ ] `[人工/移动端]` 在 320、375、390px 视口和至少一台真机打开 `/i/{shareToken}`，正文可滚动、
  无横向滚动、元素不重叠且不被固定报名按钮遮挡；轮播、视频封面、手动音乐、地图降级和 CTA 可用。
- [ ] 页面可见后记录 PV/UV，链接预览 GET 不计作 PV，重复客户端事件 UUID 不重复计数。
- [ ] `[自动化]` PAGE_VIEW 和 CTA_CLICK 的客户端事件 UUID 在普通重试和并发唯一键冲突下均幂等；
  归因 token 被篡改、过期、跨会议或跨表单时不建立错误归因。
- [ ] `[真实 TDuck/前置]` `/tduck/meetingos-capabilities.json` 返回 schemaVersion 1，且
  `capabilities.meetingosAttributionExtValue` 严格等于 `"v1"`；缺失时后台显示归因不可用提示，不能把
  该环境记为渠道归因已验收。
- [ ] `[真实 TDuck/E2E]` 从 `/i/{shareToken}` 点击 CTA，经 `/r/{meetingCode}` 到真实 TDuck 表单；
  `mos_at` 被写入该表单的 `sessionStorage` 后从地址栏清理，真实提交请求体 `extValue` 与原 token 完全
  相同，Webhook 最终按 `dataId` 归因到正确方案、发布版本和渠道。
- [ ] `[真实 TDuck/E2E]` 对同一 `dataId` 重放新增 Webhook、执行更新和补偿拉取均不重复计数、不覆盖
  首次渠道；取消后累计转化保留但当前有效报名减少，旧新增/取消事件乱序重放不能反转最新状态。
- [ ] `[故障注入]` 归因或统计写入失败时，真实报名、Webhook 和参会人同步仍成功；按同一 `dataId`
  重试不产生第二名参会人或重复转化，缺失/无效 token 仅进入明确的未归因口径。
- [ ] 统计页可按方案和日期查看 PV、UV、点击、归因报名、未归因报名和渠道趋势。

## 10. 统计与导出

- [ ] 报名统计包含总人数、待审核、通过、拒绝、今日新增、单位和类型分布。
- [ ] 座位统计包含总座位、可用、已分配、空余、禁用和使用率。
- [ ] 住宿统计包含房间数、已安排、未安排、酒店和房型分布。
- [ ] 签到统计包含应到、已签到、未签到、签到率、趋势、入口和类型分布。
- [ ] 会议管理员可配置不超过 12 个统计组件，支持系统字段和 TDuck 字段、聚合、筛选、日期范围、图表/表格及半宽/全宽布局。
- [ ] 自定义看板的非指标展示数量限制为 1 至 100；只读会议用户不能读取字段目录或执行看板查询。
- [ ] 可导出报名、审核通过名单、座位表、住宿表、签到记录、未签到名单。
- [ ] 敏感字段导出需要权限，并记录操作日志。

## 11. 安全与运维

- [ ] JWT Secret、`TDUCK_WEBHOOK_TOKEN`、数据库密码、Redis 密码、MinIO 密码为强随机值。
- [ ] `MEETINGOS_INVITATION_TRACKING_SECRET` 为独立的 32 字节以上强随机值。
- [ ] 手机号、证件号、邮箱在列表、日志、同步详情中脱敏。
- [ ] XLSX 导出仅授权人员可用，导出内容按系统设置脱敏并写审计日志。
- [ ] 生产已开启敏感导出审批；未审批的导出任务不能直接下载。
- [ ] 公共查询接口有限流，必要时有验证码或二次校验。
- [ ] MySQL、Redis、MinIO 已配置持久化和备份，且默认未暴露到公网。
- [ ] 对外 HTTPS 使用真实 TLS 配置；未配置证书时不要映射假的 443 端口。
- [ ] 镜像固定为版本 tag 或 digest，不使用 `latest`。
- [ ] 已验证至少一次备份恢复流程。
- [ ] Nginx 日志不记录完整 Token 和敏感 payload。
- [ ] `[自动化+生产 HTTPS 人工]` `MOS_INV_VISITOR` 为随机访客 Cookie，响应包含 `HttpOnly`、
  `SameSite=Lax`、`Path=/`，生产环境还包含 `Secure`；GET 邀请详情本身不写 PAGE_VIEW。
- [ ] `[数据库人工]` `invitation_events` 仅保存不可逆 `visitor_hash`、粗粒度 `device_type` 和
  `referrer_host`，不存在原始 Cookie、IP 或完整 User-Agent 字段/值；相同访客 Cookie 产生稳定哈希，
  但数据库不能反推出原始 Cookie。
